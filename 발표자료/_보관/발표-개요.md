## 구성 원칙 (왜 이 순서인가)

**1. 시연 영상을 두 번 나눠 튼다.**
1분 15초짜리 영상 하나를 12분 지점에 몰아 틀면, 그 앞 11분 동안 청중은 *"이게 실제로 되긴 하나"*를
의심하며 기술 설명을 듣는다. 하드웨어 프로젝트는 **말로 상상이 안 된다.**

- **영상 A (20초)** — 3분 지점. 화물을 재는 장면**까지만**. 결말은 안 보여준다
- **영상 B (55초)** — 12분 지점. 전 구간 완주, **포크 진입이 클라이맥스**

같은 소스에서 잘라내므로 **제작 비용은 그대로**다. A에서 결말을 감추기 때문에 중복도 아니다.

**2. 파이프라인 순서 = 슬라이드 순서.**
측정 → 적재 판단 → 포크 정렬 → 주행 → 제어 → 관제·트윈. 청중이 4번 슬라이드에서 본
흐름도를 계속 따라오게 만든다. 파트별(사람별)로 끊지 않는다 — 그러면 "6명이 각자 한 것"으로 들린다.

**3. 파트 시간을 평준화했다.**
초안은 AI가 4:30, 나머지 3명 합쳐 2:00이었다. 팀 발표에서 이 비율이면
**"AI만 한 팀"**으로 읽힌다. AI 심화 내용(도메인 갭·기하 필터)은 뒤쪽 "배운 것"으로 옮겨
**팀 전체의 원칙**으로 승격시켰다 — 같은 내용인데 인상이 완전히 달라진다.

# 시연 영상 구성

## 영상 A — 티저 (0:20, 발표 2:15 지점)

**목적**: 이후 8분의 기술 설명에 근거를 준다. "실물이 있고 실제로 돈다"를 먼저 증명한다.

| 구간 | 내용 | 길이 |
|---|---|---|
| 0:00–0:04 | 화물(파렛트+박스)이 스테이션 앞에 놓인다 | 4s |
| 0:04–0:12 | 카메라 화면에 bbox 오버레이가 뜨고 치수 숫자가 확정된다 | 8s |
| 0:12–0:18 | 관제 웹 화면에 그 값이 나타난다 | 6s |
| 0:18–0:20 | 컷 (여운 없이 딱 끊는다) | 2s |

**규칙**
- **포크 진입은 절대 넣지 않는다.** 결말을 아껴야 영상 B가 산다
- **무음** — 발표자가 위에 말을 얹는다. 발표장 음향은 못 믿는다
- 자막으로 숫자만 크게 (`높이 58.5cm`)
- 재생 직후 발표자 받는 말: *"이 숫자가 지게차까지 어떻게 가는지, 지금부터 보시겠습니다"*

## 영상 B — 풀 시연 (0:55, 발표 11:15 지점)

**목적**: 전 구간이 **한 번에 이어진다**는 것. 각 파트가 되는 건 이미 다 말했다.

| 구간 | 내용 | 길이 | 비고 |
|---|---|---|---|
| 0:00–0:03 | 타이틀 카드 — "무편집 1회 완주 / 사람 개입 없음 / 주행 구간 2배속" | 3s | |
| 0:03–0:15 | 측정 (영상 A와 같은 장면, 이번엔 **PIP로 관제 화면 동시**) | 12s | 동기화를 말 없이 증명 |
| 0:15–0:32 | 자율주행 — **2배속**, PIP에 관제 지도 마커 이동 | 17s | 배속 표기 필수 |
| 0:32–0:52 | **포크 정렬·진입** — 실속도, 클로즈업 | 20s | ★ 클라이맥스 |
| 0:52–0:55 | 포크가 물린 정지 프레임 + 결과 카드 | 3s | |

**규칙**
- **배속을 쓰면 화면에 표기한다.** 표기 없는 배속은 조작으로 읽힌다. 반대로 표기하면 감점 없다
- **"무편집 1회 완주"를 첫 카드에 박는다.** 컷 편집으로 보이는 순간 나머지 숫자까지 의심받는다
- **PIP(화면 속 화면)로 실물+관제를 동시에** — 실물→화면→실물로 왔다갔다 하면 흐름이 끊기고 시간도 두 배로 든다. PIP면 "동기화됐다"가 자동으로 증명된다
- 자막 필수, 소리 의존 금지
- **트윈(Isaac Sim) 장면은 넣지 않는다** — 실시간 동기화가 아직 미완(Jira 111·55)이다. 되면 그때 PIP 3분할로 추가
- 재생 직후 발표자 받는 말: *"측정 오차 0.66mm, 포크는 두 번 다 들어갔습니다"* → 바로 KPI 슬라이드

### 슬라이드 9 — 측정 ② 정확도 (1:00)
| 지표 | 목표 | 달성 |
|---|---|---|
| 박스 인식 mAP@0.5 | ≥ 92% | **98.98%** `[실측]` |

- 그래서 **온보드 카메라 + RTMDet-s로 파렛트·구멍을 직접 보고 맞춘다**

- [ ] 예상 질문 준비:
  - **"왜 YOLO 안 썼나?"** → RTMDet도 실시간 검출기 계열, 같은 크기대 YOLO와 동급. TensorRT 관통이 이미 끝나 속도 문제가 없고(9.28ms), 바꾸면 전 구간 재검증 + 라이선스 차이(AGPL-3.0 vs Apache-2.0)
  - **"실물 크기가 아니라 미니어처인 이유?"** → 측정은 실물 크기 화물 그대로 한다. 1/10은 주행·적재만. 치수 KPI도 실물 박스로 검증했다
  - **"치수 오차 0.66mm를 어떻게 믿나?"** → 모델 프리라벨이 아니라 자로 잰 실측 박스와 대조. 평가셋도 라벨을 비우고 처음부터 그렸다
  - **"다중 차량은 실물인가?"** → 시뮬. 실물 1대 + 시뮬 다중이 명세 단계부터의 범위 결정
  - **"왜 MQTT 쓰다가 REST로 바꿨나?"** → 스테이션 측정은 1회성 요청·응답이라 브로커를 끼울 이유가 없었다. 차량 상태 스트림은 지금도 MQTT다

- **팀원 소개 / 역할 분담표** — 평가에 안 들어간다. 파트별 발표자가 말할 때 자연히 드러난다
