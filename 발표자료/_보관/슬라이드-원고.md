## 2. 왜 이 문제인가

### 지게차는 위험해서, 늘릴 수가 없다

물류센터 지게차는 사람이 운전하는 고위험 장비다.

- 위험하니까 → 동시 운영 대수를 못 늘린다
- 못 늘리니까 → 처리량이 사람 수에 묶인다
- 자동화하면 이 사슬이 통째로 끊긴다

---

### 재고 · 정하고 · 가고 · 꽂는다

| | 단계 |
|---|---|
| ① | 화물 인식 + 치수 측정 |
| ② | 적재 위치 추천 |

**일부러 안 한 것** — 실물 크기 지게차 제작 · 장거리 트럭 연동 · WMS 실연동 · depth 카메라

넓게 벌리는 대신, 한 줄기를 끝까지 되게 만들었다

## 4. 데모 구성과 축척

### 1/10로 줄인 건 지게차지, 화물이 아니다

- 축척 **k = 10** — 실물 T-11 파렛트 1,100×1,100mm → 미니어처 11×11cm
- **측정은 실물 크기 화물 그대로** 한다. 1/10은 주행·적재만
- 스테이션은 실제 물류의 **팔레트 디멘셔너**(도크에 고정된 측정 포털)와 같은 형태다

고정 측정 스테이션 · 미니어처 지게차 1대 · 시뮬 다중 차량 — 회피가 아니라 역할 분리다

## 9. 화물 측정 — 정확도

### mAP 98.98%. 그런데 이 숫자로는 치수를 증명하지 못한다

|---|---|---|
| 박스 인식 mAP@0.5 | ≥ 92% | **98.98%** |
| 치수 오차 (미니어처 환산) | 최악 ≤ 4mm | **평균 0.66mm / 최악 2.10mm** |

KPI 판정용 평가셋은 라벨을 비우고 사람이 처음부터 그렸다.

## 13. 포크 정렬 — 실주행에서만 드러난 것

### 세 번 다, 처음 짚은 원인이 틀렸다

**진입 속도** — 세워놓고 재면 21% 높게 나온다
정지 출발이 아니라 굴러가던 중 전환이라서. 바로잡으니 예측 146mm / 실제 145mm

**요각이 정지 상태에서도 ±8.8° 튄다** — 모델 문제로 보였지만 픽셀 양자화였다
값이 2.2°의 배수로만 나온 게 증거(1px = 2.2°). 절사평균으로 폭 13° → **4.4°**

**정렬 구간 진동** — 감쇠 부족을 의심해 감쇠항을 넣었지만 아니었다
서보가 명령의 **절반만** 돌고 있었다. 펄스 범위 1000~2000us로는 MG996R이 90°밖에 안 돈다.
코드는 조향 28°로 믿었고 실측은 **8°**였다 — `tan(8)/tan(28) = 25%`
**요각 미교정 · 45° 발산 · 한계진동이 전부 이 하나에서 나왔다**

→ 45° 돌아간 파렛트에 재접근 **9회로 관통**, 포크 정상 물림

## 20. 배운 것

### 모델이 못 잡으면, 코드가 아니라 데이터를 센다
검은 파렛트는 임계 **0.02에서도 0건**. 화물이 파렛트를 덮으면 score **0.101**.
원인은 매번 학습셋 분포였다 — 가림률 30% 이상 샘플이 **0장**이었다.
전처리·임계로는 학습 분포 밖을 못 잡는다.

### 가장 비싼 버그는 에러를 내지 않는다
추론이 실패했는데 검출 0개로 나가서 서버는 **200**을 응답했다.
정지 판정 임계가 카메라 노이즈 바닥 아래라, "멈췄다"가 **영원히 성립하지 않았다**.
실패를 성공처럼 보이게 하는 반환값을 그대로 흘리지 않는다.

### 문서보다 자를 믿는다
배포 주소가 하루 사이 세 번 바뀐 적이 있다.
서보 각도는 코드가 28°라고 적어놨지만 실제는 8°였다.
그 뒤로 주소도 수치도 매번 다시 잰다.
