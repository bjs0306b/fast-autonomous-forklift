# 오린카 랙 좌표 명세 (C팀용)

랙에 화물을 놓거나 꺼낼 때 필요한 좌표와 절차. 이 문서 하나로 구현할 수 있다.
MQTT 규격은 [orin-pose-spec.md](orin-pose-spec.md) 를 본다.

기계가 읽을 파일도 같이 제공한다.

    nav2/config/rack_slots.json     프로그램용
    nav2/config/rack_slots.csv      표 (시뮬·실물 두 단위)

---

## 0. 세 줄 요약

1. 슬롯마다 **approach / dock / place** 세 좌표가 있다
2. **방향은 전부 `yaw = 3.1416` (서쪽 −x)** — A랙 B랙 똑같다
3. approach 까지만 Nav2, **approach → dock 은 저속 직진** (Nav2 로는 못 간다)

---

## 1. 좌표 단위

이 문서의 표는 **실물 미터**다. MQTT 로 오는 값은 시뮬 좌표계라
**÷10** 하면 이 표의 값이 된다.

```
MQTT  {"x": 5.00, "y": 9.30}   ÷10 →   실제로 갈 곳 (0.500, 0.930) m
```

`yaw` 는 라디안이라 **변환하지 않는다**.

---

## 2. 랙 배치

```
        y
   2.475 ┌───┐            ┌───┐        ← 랙 위쪽 끝
         │   │            │   │
         │ A │            │ B │
         │   │            │   │
   0.845 └───┘            └───┘        ← 랙 아래쪽 끝
         0.010          0.945
             0.150          1.085      ← 진입면(도킹 기준)
```

| 랙 | x 범위 (m) | y 범위 (m) | 진입면 |
|---|---|---|---|
| **A** | 0.010 ~ 0.150 | 0.845 ~ 2.475 | **0.150** (동쪽) |
| **B** | 0.945 ~ 1.085 | 0.845 ~ 2.475 | **1.085** (동쪽) |

두 랙 모두 **동쪽 면**이 진입면이다. 그래서 지게차는 언제나 **서쪽(−x)을
보고** 들어간다.

---

## 3. 방향 — 전부 `yaw = 3.1416`

```
      A랙                            B랙
  ┌────┐                        ┌────┐
  │    │ ◀━━━━━ ●               │    │ ◀━━━━━ ●
  └────┘  yaw = π               └────┘  yaw = π
  0.150  0.260   0.500          1.085  1.195   1.450
   진입면  dock  approach         진입면  dock  approach
```

approach · dock · place **세 좌표 모두 같은 방향**이다.

`±π` 는 같은 방향이므로, 각도 오차는 반드시 감싸서(wrap) 계산한다.

```python
err = math.atan2(math.sin(target - yaw), math.cos(target - yaw))
```

그냥 빼면 179° 와 −179° 가 358° 차이로 나와 차가 한 바퀴 돌려고 한다.

## 5. 세 좌표의 뜻

| 좌표 | 쓰는 법 |
|---|---|
| **approach** | Nav2 `navigate_to_pose` 목표. 여기까지는 자율주행 |
| **dock** | 포크를 랙에 넣었을 때의 차량 중심. **Nav2 로는 못 간다** |
| **place** | 파레트가 놓이는 자리. 참고용 (포크를 내리면 여기 놓인다) |

**dock 은 차체가 랙과 겹치는 자리**라 Nav2 가 "경로 없음" 을 낸다.
포크를 랙 안에 넣어야 하니 당연한 일이다. 이 구간만 직접 몬다.

## 6. 적재 절차 (`PLACE_RACK`)

관제가 이런 지시를 보낸다 (좌표는 시뮬 단위).

```json
{ "taskId": "T-0043", "action": "PLACE_RACK", "rack": "A1", "cargoId": "C-0007",
  "approach":    { "x": 5.00, "y": 9.30, "yaw": 3.1416 },
  "dock":        { "x": 2.60, "y": 9.30, "yaw": 3.1416 },
  "shelfHeight": 1.325,
  "reverseDist": 2.0 }
```

받으면 **÷10** 해서 아래 순서로 수행한다.

```
1. approach (0.500, 0.930) 까지 Nav2 로 주행
2. yaw 를 3.1416 에 맞춘다          ← 여기가 안 맞으면 3번이 무의미
3. dock (0.260, 0.930) 까지 240 mm 저속 직진   ← Nav2 를 쓰지 않는다
4. 포크를 0.1325 m 로 올린 뒤 내린다 (화물이 선반에 얹힌다)
5. 200 mm 후진
6. event 로 UNLOAD_DONE 발행
```

절차 전 구간의 `state` 는 **`UNLOADING`** 으로 보낸다.

### 허용 오차

| 단계 | 허용 |
|---|---|
| approach 도착 | ±30 mm, ±10° |
| **dock 진입 직전 각도** | **±3°** |
| 최종 포크 위치 | ±12 mm |

240 mm 직진에 3° 틀어지면 끝에서 **12 mm** 밀린다. 그게 한계다.

### ToF 로 보정할 것

오도메트리만으로 240 mm 에 12 mm 정밀도는 빠듯하다. 앞쪽 ToF 로 랙 면까지
거리를 재며 들어가는 편이 안전하다.

```python
# 랙 면에서 남길 거리 = dock(0.260) - 진입면(0.150) = 0.110 m
while tof_front() > 0.110:
    drive_slow()
```

좌우 ToF 가 있으면 **평행 정렬**까지 된다.

```python
if abs(tof_left - tof_right) > 0.005:    # 5 mm 이상 차이
    조향 보정                              # 랙 면과 평행하게
```

## 7. 반출 절차 (`PICK_RACK`)

`PLACE_RACK` 의 역순이다. 포크를 선반 아래로 넣고 살짝 올려 화물을 든 뒤
후진한다. 완료 후 `event` 로 `LOAD_DONE` 을 발행한다.

절차 중 `state` 는 **`LOADING`**.

## 9. 랙 좌표를 직접 들고 있을 필요는 없다

관제가 `task` 로 approach·dock·shelfHeight 를 **매번 보내준다.** 이 문서의
표는 **검증용**이다 — 관제가 준 값이 맞는지 대조할 때 쓴다.

`rack_slots.json` 을 읽어 자체 검증을 넣어두면 좋다.

```python
import json
SLOTS = json.load(open("rack_slots.json"))["slots"]

def check(rack, got_x, got_y):          # got_* 는 이미 ÷10 한 실물 m
    want = SLOTS[rack]["approach"]
    dx = abs(got_x - want["x"] / 10)
    dy = abs(got_y - want["y"] / 10)
    if dx > 0.02 or dy > 0.02:
        print(f"경고: {rack} 좌표가 표와 다릅니다 ({dx*1000:.0f}, {dy*1000:.0f} mm)")
```

## 10. 확인이 필요한 값

| 항목 | 현재 가정 | 확인 |
|---|---|---|
| 1층 선반 높이 | 0.1325 m | 실측 140 mm 라면 0.140 으로 조정 |
| 랙 길이 | 1.630 m | 실측 1.600 m 면 슬롯 y 를 다시 뽑는다 |
| 랙 폭 | 0.140 m | 진입면 위치만 맞으면 무관 |

선반 높이가 다르면 알려주면 `shelfHeight` 를 바꿔 보내겠다.
