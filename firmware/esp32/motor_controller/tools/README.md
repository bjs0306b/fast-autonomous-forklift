# 브링업 검증 도구

USB 상행 링크(`/dev/ttyACM0`)로 붙어 프레임을 직접 뜯어보는 도구들입니다.
ROS2를 띄우지 않고 펌웨어만 확인할 때 씁니다.

프레임 파서는 `ros2_ws/src/forklift_teleop`의 `sensor_protocol.py`를 그대로
가져다 씁니다 — 브리지가 쓰는 것과 같은 코드로 검증해야 의미가 있습니다.

> **주의**: 포트를 여는 순간 ESP32가 리셋되고 **포크 호밍이 한 번 돕니다.**
> 포크 주변을 비우고 실행하세요. 그래서 IMU·ToF 데이터는 부팅 후 20초쯤
> 지나야 나오기 시작합니다.

## `tof_probe.py`

ToF 두 개와 IMU를 한 번에 확인합니다.

```bash
python3 tools/tof_probe.py [초]      # 기본 60초
```

- I2C1 스캔 로그, 주소 배정 결과, 펌웨어 업로드 성공 여부
- 센서별 `@TOF` 수신율·결번, **유효 존만의 거리**와 상태 분포
- `@IMU` 무회귀 확인 — ToF를 얹어도 100Hz·결번 0이 유지되는지
- **ESP32 재부팅 감지** — 시퀀스가 역행하면 구간을 나눠 보고합니다

프레임이 안 나올 때 로그에서 볼 순서:

| 로그 | 원인 |
|---|---|
| `answered neither 0x29 nor 0x2A` | 배선, `SPI_I2C_N` |
| `address did not stick` | **`SPI_I2C_N` 플로팅** — 가장 흔했던 원인 |
| `sensor init failed` | 84KB 펌웨어 업로드 실패, 풀업 |
| `is being polled` | INT 배선 (동작은 하되 지터 증가) |

## `gyro_scale_check.py`

자이로 스케일을 90도씩 네 번 끊어 돌려 검증합니다.

```bash
python3 tools/gyro_scale_check.py
```

종이에 십자선을 긋고 보드 한 변을 맞춘 뒤, 다음 선에 맞을 때까지 돌리면
정확히 90도입니다. **속도는 상관없습니다** — 적분은 속도 프로파일과 무관하고,
90도를 1초보다 빠르게만 돌리지 않으면 ±250 dps 포화도 피합니다.

감도는 `main/config.h`에서 직접 읽습니다. 도구에 상수를 복사해 두면 펌웨어와
어긋났을 때 조용히 배율이 틀어집니다.

**구간 편차가 크면 스케일 문제가 아닙니다.** 감도는 곱셈 상수라 네 구간을 같은
비율로 바꿉니다. 구간이 점점 줄어들면 바이어스 추적기가 회전을 흡수하는
것이고, 그건 `task_imu.c`의 정지 판정 게이트를 봐야 합니다.
