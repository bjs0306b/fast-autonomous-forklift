# 🛠️ [Troubleshooting] Jetson Orin Nano 비전 환경 구축 및 PyTorch 설치 에러 해결

## 🖥️ 개발 환경 (Environment)
*   **Hardware:** NVIDIA Jetson Orin Nano
*   **OS / JetPack:** JetPack 6.2 (Ubuntu 22.04, CUDA 12.6)
*   **Python:** Python 3.10
*   **Workspace:** ROS2 환경 (`~/ros2_ws`)

---

## 🛑 Issue 1. Jetson AI Lab PyTorch Wheel 파일 다운로드 실패 및 버전 변경

### 🚨 증상 (Symptom)
기존에 알려진 가이드대로 `wget`을 통해 PyTorch와 torchvision의 `.whl` 파일을 다운로드하려 했으나, 사이트 접속이 불가능하거나 파일을 찾을 수 없는 문제 발생. 

```bash
# 실패한 기존 명령어 (주소 만료)
$ wget [https://pypi.jetson-ai-lab.dev/jp6/cu126/.../torch-...whl](https://pypi.jetson-ai-lab.dev/jp6/cu126/.../torch-...whl)

```

### 🔍 원인 파악 (Root Cause)

1. NVIDIA Jetson AI Lab의 커스텀 패키지 서버 도메인이 `.dev`에서 `.io`로 변경됨.
2. 젯팩 6.2 환경에 맞춰 지원되는 배포 버전이 상향되어 기존 버전 대신 최신 버전을 설치해야 함.

### 💡 해결 방법 (Solution)

도메인 주소를 `.io`로 변경하고, 의존성 패키지 누락을 방지하기 위해 `wget` 다운로드 방식 대신 `pip`의 `--extra-index-url` 옵션을 사용하여 변경된 최신 버전(PyTorch 2.11.0, torchvision 0.26.0)을 직접 설치.

```bash
# 수정된 설치 명령어 (도메인 및 버전 업데이트)
$ pip install torch==2.11.0 torchvision==0.26.0 --extra-index-url [https://pypi.jetson-ai-lab.io/jp6/cu126](https://pypi.jetson-ai-lab.io/jp6/cu126) --upgrade

```

## 🛑 Issue 2. PyTorch `import` 시 `libcudss.so.0` 라이브러리 인식 불가 에러

### 🚨 증상 (Symptom)

설치 완료 후 파이썬 스크립트(`test.py`)에서 `import torch`를 실행했을 때 아래와 같은 `ImportError` 발생.

```bash
orin@orin-desktop:~/ros2_ws$ /usr/bin/python /home/orin/test.py
Traceback (most recent call last):
  File "/home/orin/test.py", line 1, in <module>
    import torch
  File "/home/orin/.local/lib/python3.10/site-packages/torch/__init__.py", line 442, in <module>
    from torch._C import *  # noqa: F403
ImportError: libcudss.so.0: cannot open shared object file: No such file or directory

```

### 🔍 원인 파악 (Root Cause)

1. 시스템 내에 `libcudss.so.0` 파일이 존재하기는 하나, 시스템 링커가 해당 파일을 자동으로 찾지 못함.
2. 파일의 실제 위치를 확인해 본 결과, 파이썬 로컬 패키지 경로인 `~/.local/lib/python3.10/site-packages/nvidia/cu12/lib` 하위에 설치되어 있었음.
3. ROS2 워크스페이스(`~/ros2_ws`) 환경 설정과 시스템 라이브러리 참조 경로가 꼬이면서 런타임에 동적 라이브러리(`.so`)를 찾지 못하는 문제(Dynamic Linking Issue).

### 💡 해결 방법 (Solution)

환경 변수(`LD_LIBRARY_PATH`)를 수정하는 대신, 시스템 전체가 해당 `.so` 파일을 안정적으로 참조할 수 있도록 전역 라이브러리 경로(`/usr/lib`)에 심볼릭 링크(Symbolic Link)를 생성하여 해결.

```bash
# 1. 시스템 전역 경로에 심볼릭 링크 생성
$sudo ln -s$HOME/.local/lib/python3.10/site-packages/nvidia/cu12/lib/libcudss.so.0 /usr/lib/libcudss.so.0

# 2. 동적 링커 캐시 업데이트
$ sudo ldconfig

# 3. 테스트 실행 (에러 없이 정상 import 확인)
$ /usr/bin/python /home/orin/test.py

```

---

**📝 Summary:** JetPack 6.2 환경에서 PyTorch 설치 시, 변경된 패키지 서버 도메인(`.io`)을 사용해 최신 버전(2.11.0 / 0.26.0)을 설치해야 함. 또한 런타임 라이브러리 인식 에러(`libcudss.so.0`) 발생 시, 패키지 내부에 숨겨진 공유 라이브러리를 전역 경로에 심볼릭 링크로 연결하여 ROS2 등 다른 환경 변수의 간섭 없이 안정적으로 구동되도록 설정함.
