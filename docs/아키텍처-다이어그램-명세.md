# 아키텍처 다이어그램 작성 명세

이 문서는 **아키텍처 다이어그램을 그리기 위한 것**이다. 블록·연결·표기만 담는다.

작성 기준일: 2026-08-12
근거: 레포 실물 대조 (`pom.xml`, `frontend/monitoring-control-system/package.json`, `docker-compose.yml`, `infra/mqtt/docker-compose.yml`, `firmware/esp32/motor_controller/main/config.h`, `ai/src/station/config.py`)

시스템은 **화물을 재는 스테이션 · 화물을 나르는 무인 지게차 · 둘을 지휘하는 클라우드 백엔드 · 현장을 비추는 디지털 트윈** 네 덩어리이고, 네 덩어리는 **REST와 MQTT 두 가지로만** 대화한다.

## 3. 연결

실선은 데이터 흐름, 점선은 스트리밍·동기화. 라벨은 아래 문자열을 **그대로** 쓴다.

| # | 구간 | 방식 | 라벨 | 검증 상태 |
|---|---|---|---|---|
| 1 | Frontend ↔ Backend | REST | `REST API` | 완료 |
| 2 | Frontend ↔ Backend | WebSocket | `WebSocket / STOMP` | 완료 |
| 3 | Backend → Database | JDBC | `SQL` | 완료 |
| 4 | Backend ↔ Messaging | MQTT (Eclipse Paho) | `MQTT (Paho)` | 완료 |
| 5 | Messaging → 측정 스테이션 | MQTT TLS | `fast/station/measure_request` | 왕복 검증 완료 |
| 6 | 측정 스테이션 → Backend | REST | `POST /api/stations/measurements` | 왕복 검증 완료 |
| 7 | Messaging ↔ Edge(Jetson) | MQTT TLS `:8883` | `forklift/{vehicleId}/command` · `.../command-result` | 부분 |
| 8 | Edge(Jetson) ↔ Embedded(ESP32) | UART 115200 8N1 | `CRC-16 · 500ms 워치독` | 완료 |
| 9 | Digital Twin → Streaming Relay | RTSP `:8554` | `RTSP (ffmpeg)` | 송출 확인 |
| 10 | Streaming Relay → Frontend | WebRTC `:8889` | `WebRTC 재생` | 시연 망 UDP 차단 |
| 11 | Digital Twin → Frontend | Omniverse WebRTC `:49100`·`:47998` | `Omniverse WebRTC (직결)` | 9·10으로 대체 |
| 12 | Digital Twin ↔ Messaging | MQTT | `상태 동기화` | 미검증 |

**9·10과 11은 서로 다른 파이프라인이다.** 하나로 뭉뚱그리면 틀린 그림이 된다. 11은 Omniverse 자체 WebRTC SDK 직결이고, 9·10은 워크스테이션 ffmpeg가 화면을 캡처해 MediaMTX로 중계하는 경로다.

### 3-1. 그리면 안 되는 연결

**Database ↔ Messaging 직결.** MySQL과 Mosquitto는 서로 모른다. MQTT로 들어온 메시지는 전부 백엔드(Spring Integration MQTT)를 거쳐 MyBatis로 DB에 반영된다. 이 화살표가 있으면 틀린 그림이다.

### 3-2. 검증 상태 표기

범례에 검증 상태를 함께 싣는다. **완료는 초록, 미완은 주황**으로 구분한다. 심사에서 "어디까지 됐냐"는 질문이 반드시 나오므로 그림이 스스로 답하게 만든다.

미완으로 칠할 것 — 7번(백엔드 → Nav2 MOVE는 배선까지만 검증, 실주행 미검증 / Jetson ↔ 브로커는 지금 없어진 평문 브로커 기준 검증이라 TLS 재검증 필요), 10번, 12번. 여기에 **Nav2 ↔ 포크 정렬의 `/cmd_vel` 인계 규칙 없음**을 지게차 그룹 안에 표시한다.

## 4. 이 시스템에 **없는** 것

그림에 들어가면 사실과 다르므로 넣지 않는다.

- **CVAT** — 라벨링은 레포 자체 도구(`ai/src/dataset/label_onboard.py`)로 했다. 경로·파일 이름에 `cvat`가 남아 있지만 이름뿐이다.
- **YOLO / Ultralytics** — 검토했으나 채택하지 않았다.
- **OV5647 CSI 카메라** — 커넥터·드라이버 문제로 USB 카메라로 교체했다.
- **강화학습 기반 포크 정렬** — 기하로 정확히 계산되는 관계라 채택하지 않았다.
- **GPU 서버의 런타임 서비스** — Mosquitto·Isaac Sim·Nav2 모두 2026-08-03에 내려갔다. GPU 서버는 학습 전용이다.
- **지게차 위의 PyTorch / MMDetection / ONNX Runtime** — 학습 스택과 스테이션 스택이다. 지게차에서 도는 것은 TensorRT뿐이다.
- **지게차 위의 Logitech BRIO / TF-Nova** — 측정 스테이션 장비다. 지게차 카메라는 1280×720 USB 카메라다.

## 6. 그리기 규칙

- **번호**: 1~11을 빠짐없이, 중복 없이. 지금까지 만든 판마다 번호가 빠지거나(9번, 5번) 겹쳤다(7번 두 개, 8번 두 개, 11번 두 개).
- **언어**: 설명 문구는 한국어로 통일한다. 블록 제목만 영문 고유명사를 쓴다(`1) Frontend`, `8) Edge`). 한 그림 안에서 어떤 블록은 영어 설명, 어떤 블록은 한국어 설명이 되지 않도록 한다.
- **화살표**: §3 표 그대로. 라벨은 §3의 "라벨" 열 문자열을 그대로 쓴다.
- **범례**: 그룹 색 + 검증 상태(완료 초록 / 미완 주황) + "그리면 안 되는 연결"을 함께 싣는다.
