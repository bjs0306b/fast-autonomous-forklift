## 1. 준비 — 순서대로

### ① Nav2 를 내린다

`behavior_server`가 살아 있으면 복구 동작이 `/cmd_vel`에 끼어들어 **차가 주기적으로 "틱" 하고 혼자 돈다.** 08-04에 퍼블리셔가 6개 붙어 있는 것을 실제로 봤다.

```bash
ros2 node list | grep -E "behavior_server|controller_server|bt_navigator"
```

나오면 내린다. 인계 규칙 자체는 아직 없다 — **S15P11A304-199**.

### ② 모터 브리지를 띄운다

```bash
ros2 launch forklift_teleop teleop_uart.launch.py
```

### ③ 포크 높이를 손으로 맞춘다

**7mm** (바닥에서 포크 날 밑면까지). 자동으로 맞추는 단계가 시퀀스에 없다(관련: S15P11A304-104).

미니어처 파렛트 실측 단면 — 총높이 **14mm**:

```
   상판   2mm
   구멍  10mm   ← 여기로 들어간다. 중심이 바닥에서 2 + 10/2 = 7mm
   하판   2mm
```

⚠️ **종전에 이 자리에 적혀 있던 "50~60mm" 는 틀린 값이다** (2026-08-04 정정). 파렛트 **전체 높이가 14mm** 인데 50~60mm 면 포크가 파렛트 위를 지나간다. 근거도 "너무 낮으면 바닥에 걸린다" 하나뿐이었고 구멍을 재서 나온 값이 아니었다.

⚠️ 높이 허용오차는 **±2.25mm** 로 빡빡하다(`onboard-hole-label-guide.md`). 비전은 가로·요만 책임지고 높이는 스텝모터·리밋스위치 담당이라, 손으로 맞출 때 눈대중으로 잡으면 안 된다.

포크 좌우 **수평도 눈으로 확인**한다. 10mm 구멍이라 한쪽이 처지면 그 차이가 바로 걸림이 되고, 진입할 때 파렛트가 그쪽으로 밀린다 — 정렬 오차로 오진하기 쉽다.

### ④ 구독자 수를 확인한다 ← 건너뛰지 말 것

```bash
ros2 topic info /cmd_vel
```

**구독자가 1**이어야 한다. 0이면 도메인이 안 맞은 것이고(아래 함정 2), 2 이상이면 Nav2가 안 내려간 것이다.

## 2. 실행

```bash
cd ~/S15P11A304/ai
export ROS_DOMAIN_ID=100
PYTHONPATH=src:$PYTHONPATH python3 scripts/onboard_fork_align_node.py \
    --engine ~/trt_test/onboard_s640_ep116_fp16.engine \
    --plugin ~/mmdeploy/build_trt/lib/libmmdeploy_tensorrt_ops.so \
    --camera 0 --rotate180 --dry-run
```

⚠️ **처음에는 반드시 `--dry-run`.** 명령을 계산해 찍기만 하고 `/cmd_vel`을 안 낸다. 좌우 부호가 반대면 지게차가 파렛트로 돌진한다 — 로그로 부호부터 확인하고 떼어낸다.

`--fork-center-x`(670)·`--focal-px`(1277.7)는 **실측 기본값이 코드에 박혀 있어** 안 줘도 된다. 카메라를 옮겼으면 다시 재서 준다(`scripts/pallet_ruler.py`, `scripts/calibrate_camera.py`).

### 종료 코드

| 코드 | 뜻 |
|---|---|
| `0` | DONE — 진입 성공 |
| `2` | ABORT — 진입 거리에서 정렬이 안 맞음 |
| `3` | SEARCH — 파렛트를 **한 번도 못 봄**(타임아웃) |
| `4` | STALLED — 명령은 나가는데 **차가 안 움직였다**. 제어가 아니라 브리지·배터리·UART를 본다 |
| `5` | 시작 시 `/cmd_vel` **구독자가 없다** — 모터 브리지가 죽었다 |

⚠️ **0만 성공으로 센다.** 종전에는 SEARCH도 0을 돌려줘서 성공률이 조용히 부풀려졌다(S15P11A304-191에서 분리).

⚠️ **4를 2와 가른 이유** (2026-08-05): 멎음은 정렬 실패가 아니라 **하드웨어 실패**라 사람이 볼 곳이 완전히 다르다. 그날 브리지 사망(10:13)·UART 링크 이상(10:57)으로 세 번 멎었는데, 매번 정렬 노드가 60~90초 동안 `align`을 정상처럼 찍어서 "정렬이 왜 안 되지"로 시간을 태웠다. 실제로 봐야 했던 것은 `pgrep uart_teleop_bridge`와 배터리였다.

## 3. 함정 — 전부 조용히 실패한다

### ① `PYTHONPATH=src` 로 쓰면 `rclpy` 를 못 찾는다

**반드시 `PYTHONPATH=src:$PYTHONPATH`.** 맨 앞만 쓰면 ROS 경로를 통째로 덮어써서 `ModuleNotFoundError: rclpy`가 난다. 08-04에 두 번 밟았다.

### ② `setsid`·`nohup` 은 `ROS_DOMAIN_ID` 를 상속하지 않는다

지게차 ROS2는 도메인 **100**을 쓴다(`docs/deploy/ros-domain.md` — 기본 도메인에는 팀원의 Isaac Sim이 같은 `/cmd_vel`에 들어와 있다).

백그라운드로 던지는 스크립트라면 **스크립트 안에 `export ROS_DOMAIN_ID=100`을 직접 넣는다.** 안 넣으면 `/cmd_vel` 구독자가 0이라 **차가 안 움직이는데 에러도 안 난다.**

### ③ `pkill -f <패턴>` 이 자기 SSH 세션을 죽인다

패턴이 **자기 명령줄에도 매칭**돼서 SSH가 exit 255로 끊긴다. 대괄호(`pkill -f "[o]nboard_fork"`)를 쓰거나 PID를 직접 지정한다.

⚠️ **대괄호만으로는 부족하다** (2026-08-04에 두 번 더 밟았다). 대괄호는 **그 한 군데**만 가리는데, `pkill` 로 죽이려는 이름이 같은 명령줄의 **다른 곳에도** 있으면(예: 뒤에서 `ros2 run ... uart_teleop_bridge` 로 다시 띄우는 줄) 거기에 매칭돼 또 자살한다. 증상은 **아무 출력 없이 끝남**이라 원인이 안 보인다.

문자열을 쪼개서 리터럴이 아예 안 나타나게 하는 것이 확실하다:

```bash
PAT="uart_teleop""_bridge"     # 명령줄에는 따옴표가 낀 형태로만 남는다
pkill -f "$PAT"
```

### ③-2 `ros2 launch` 를 죽여도 노드는 산다

`pkill -f "teleop_uart.launch"` 는 **launch 프로세스만** 죽인다. 자식 `uart_teleop_bridge` 는 살아남아 20Hz로 계속 UART에 쓴다.

⚠️ **리눅스 시리얼은 기본이 배타 잠금이 아니다.** 그래서 두 번째 발신자가 포트를 **열기는 하고**, 두 쪽 프레임이 번갈아 들어가 **차가 안 움직인다.** 에러가 없어서 "모터가 죽었나" 로 오진하기 딱 좋다 — 08-04에 브리지가 **3개**까지 쌓여 있었다.

시작 전에 확인한다:

```bash
pgrep -af "uart_teleop""_bridge"     # 1개여야 한다
```

### ④ `linear.x` 는 속도 단위가 아니다

`linear.x` 는 PWM 퍼센트로 매핑될 뿐이다. 지금은 하한 35 / 상한 60 이라 명령이 실제로 갈리지만(0.06 → 43% ≈ 0.122 m/s, 0.20 → 60% ≈ 0.257 m/s), **비례하지는 않는다.**

⚠️ **35% 아래로는 못 간다.** 구르던 차도 멎고, 멎으면 정지마찰 때문에 **스스로 다시 출발하지 못한다.** 그래서 `--align-speed` 는 0.02 가 하한이다.

⚠️ 진입 시간을 명령값으로 계산하면 안 된다 — `INSERT_SPEED_ACTUAL` 을 따로 둔 이유다. 그 값은 **실주행 로그의 `distance_mm` 시계열**에서 뽑는다(§6).

**이력**: 2026-08-04 오전까지는 하한이 50 이라 폭이 10%p 뿐이었고, `linear.x` 를 어떻게 주든 실제 속도가 한 가지로 뭉개졌다. 게인·속도를 만져도 거동이 안 변해 하루를 태웠다 — **제어 파라미터가 반응하지 않으면 제어 루프 밖을 의심할 것.** → S15P11A304-198 에서 해결.

⚠️ **고정 횟수 루프로 짜지 말 것.** 08-04에 둘 다 사고를 냈다:

값을 바꿀 때마다 상수를 고치고 젯슨에 복사하지 않아도 된다.

| 플래그 | 기본 | 쓰는 곳 |
|---|---|---|
| `--align-speed` | 0.06 | ALIGN 전진 속도. ⚠️ **0.02 미만 금지** — drive 35% 아래라 구르던 차도 멎고, 멎으면 정지마찰로 스스로 못 출발한다 |
| `--k-lateral` | 0.25 | 좌우 오차 게인 |
| `--insert-margin` | 40 | 진입 여유(mm). 줄일수록 깊이 들어간다. ⚠️ 한 단계씩 |
| `--yaw-window` | 5 | 요각 평활 창(프레임). 1이면 생값 |
| `--lateral-tolerance` | 0.25 | 진입 허용 좌우 오차. ⚠️ **튜닝 값이 아니라 시험용 손잡이다** — 작게 주면 정상 정렬도 미정렬로 판정돼 재접근이 확실히 발동한다 |
| `--yaw-deg-tolerance` | 10 | 진입 허용 **요각**(도). ⚠️ 이게 없던 동안 요각 -58.5°인 채로 진입이 허가돼 포크가 비스듬히 스쳤다 |
| `--max-retries` | 20 | 진입 거리에서 미정렬일 때 물러나 재접근하는 횟수(154). **0이면 종전처럼 즉시 ABORT**. 실질 예산은 `--max-seconds` |
| `--retreat-target` | 600 | 거리를 **모를 때만** 쓰는 자리표시자. 거리를 알면 틀어진 만큼 계산한다 |
| `--retreat-max-s` | 5.0 | 후진 시간 상한(초). **목표가 아니라 안전 상한**이다 |
| `--retreat-steer` | -1.0 | 후진 중 조향 세기. **1.0 = 최대 조향, 음수 = 방향 반전**(실측으로 음수가 맞다). 0이면 곧게 물러난다 |

## 5-2. 재접근 (S15P11A304-154)

진입 거리(210mm)에서 정렬이 안 맞으면 그 자리에서 끝내지 않고 **틀어진 만큼 물러났다가 다시 접근**한다. 뒷바퀴 조향은 제자리 회전이 안 되므로 코앞에서는 못 고친다.

```
ALIGN ──진입거리──> VERIFY ──정렬됨──> INSERT ──> DONE
                      └─미정렬─> RETREAT ─물러남─> APPROACH ──> ALIGN ...
                                    └─ 재시도 소진 / 시간 상한 / 복귀 실패 ──> ABORT
```

- **VERIFY — 한 프레임으로 진입을 정하지 않는다.** 3프레임을 모아 **중앙값**으로 판단한다. 08-05에 튄 프레임 하나가 `distance_mm`을 149mm(실제 350mm)로 찍어 진입이 확정됐고, 지게차가 **110mm만 가고 멈춘 채 `done`을 찍었다.** 판단 중에는 조향을 끊고(이 거리에서 꺾으면 구멍 벽을 긁는다) 굴러가는 상태는 유지한다(멈추면 정지마찰로 못 출발한다).
- **요각 게이트** — 각도를 알면 각도로 판정한다(기본 10°). `yaw_signal`은 큰 각도에서 포화돼(실제 -58.5°가 -0.07) 허용치를 통과시킨다. 그래서 포크가 구멍에 안 들어가고 **비스듬히 스쳤는데 로그는 `done (inserted)`**였다.
- **후진량은 틀어진 만큼 계산한다** — 요각은 `R·sin ψ`, 좌우는 실측 "10cm에 45cm"에서 유도. 둘 중 큰 쪽, 80~120mm로 자른다. 고정값(종전 390mm)은 조금 틀어졌을 때 낭비고 크게 틀어졌을 땐 모자랐다.
- **후진 속도 -0.12 m/s**. 정지 출발이라 그 아래로는 안 움직인다.
- **후진 조향은 요각만 본다.** 좌우까지 넣었더니 두 항이 상쇄돼 요각 40°를 남기고 조향이 0으로 죽었다. 좌우는 다음 접근 구간이 지운다.
  - **부호는 음수(`-1.0`)가 맞다** — 실측으로 갈랐다. `+1.0`은 `lat`이 +0.33 → +4.8로 발산하고 요각도 나빠졌다. `map_twist`가 `곡률 = angular_z / linear_x`로 조향각을 내는데 `linear_x`가 음수면 부호가 뒤집히고, 링키지 극성은 전진으로만 맞춘 값이라 그 뒤집힘이 상쇄되지 않는다.
- **시야 유지** — `lat`이 1.2를 넘으면 요각 교정을 멈추고 좌우부터 되돌린다. 타깃을 놓치면 재접근 자체가 끝나므로, 자세를 덜 펴더라도 화면 안에 두는 쪽이 낫다.
- **놓쳐도 바로 안 끝낸다** — 마지막으로 본 방향으로 꺾어 2초간 되찾아본다. 파렛트는 화면 옆으로 밀려 사라지므로 그쪽으로 돌리면 다시 들어오고, 후진 중이라 시야도 넓어진다.

⚠️ **뒤는 카메라가 안 본다.** 거리 판정은 파렛트가 멀어지는 것으로만 하므로 뒤에 뭐가 있는지는 아무도 모른다. 방어는 두 겹이다 — 매 프레임 거리 확인(닫힌 루프) + 시간 상한 5.0초. 상한에 걸리면 `retreat_timeout`으로 실패 처리한다. **시작 전에 뒤가 비었는지 사람이 본다.**

⚠️ **꺾은 채 후진하려면 힘이 더 든다.** 뒷바퀴가 후진 시 앞장서는데(leading) 36° 누우면 바닥을 옆으로 긁는다. 60%로는 45° 재접근에서 **5초간 한 발도 못 갔고**, `max_drive_percent_reverse: 100`으로 올리자 정상 동작했다. 전진 상한은 60% 그대로다.

`outcome` 으로 실패를 가른다: `misaligned_at_insert`(재시도 소진) · `retreat_timeout`(거리 판정이 죽음) · `lost_while_retreating`(복귀 실패) · `started_too_close`(출발부터 진입 거리 안쪽) · `stalled`(명령은 나가는데 안 움직임).

## 6. 현재 상태 (2026-08-05)

**45° 로 돌아간 파렛트에 관통했다** — `done (inserted)`, 재접근 9회, 포크가 제대로 물렸다. 아침 기준으로는 손도 못 대던 조건이다.

### 🔴 오늘의 뿌리 원인 — 조향이 명령의 1/4만 들어가고 있었다

`firmware/.../servo.c` 가 각도를 **180으로 정규화해 `SERVO_MIN/MAX_PULSE_US` 사이에 매핑**하는데, 그 범위가 `1000~2000µs` 였다. MG996R 은 **500~2500µs 가 180°** 이고 1000~2000 으로는 90~120° 밖에 안 돈다.

```
중립 9400cdeg = 94°  →  1000 + 94/180×1000  = 1522µs
최대 12200    = 122° →  1000 + 122/180×1000 = 1678µs
                                       차이 =  156µs  ≈ 서보 14°  (코드는 28°로 믿음)
```

숫자 셋이 맞물려서 잡혔다 — **뒷바퀴 실측 8°**, **실효 회전반경 1200~1450mm**(설계값 537mm 의 2~3배), **명령 대비 실제 회전 21~26%**. `tan(8°)/tan(28°) = 25%` 다.

이 하나가 그동안 "제어가 이상하다" 로 보이던 것들의 정체다 — ALIGN 이 요각을 못 지움, 후진 250mm 에 12° 만 펴짐(모델 예측 27°), 45° 에서 발산, 한계진동.

|---|---|---|
| 서보 펄스 범위 | 1000~2000µs | **500~2500µs** |
| 뒷바퀴 실각도 | 8° | **36°** |
| 조향 중립 | 9400 | **9000** |

**봉투와 운전값을 분리했다** — `protocol.py`·펌웨어는 "여기까지 허용"(4000~14000 · drive ±100), 실제 값은 `teleop.yaml` 하나에서만 정한다. 이제 범위를 바꿔도 재플래시가 필요 없다. 브리지도 기본값을 다시 적지 않고 `TeleopLimits` 에서 가져온다.

구조가 설명한다 — 조향각 → 요레이트 → 헤딩 → 좌우위치로 **적분이 두 번** 들어간다. 이중적분기에 비례제어만 걸면 감쇠가 0이라 반드시 진동하고, **게인을 낮추면 주기만 길어진다.** 게다가 설계가 좌우·요를 **같은 부호로** 더하므로(면 법선 진입 목적), 감쇠 역할을 해야 할 요 항이 오히려 보강 쪽으로 작동한다. ALIGN의 요 게인 ×2가 그걸 더 세게 만든다.

- 진폭이 확 줄면 → 게인 문제
- **주기만 길어지고 진폭은 그대로면 → 감쇠 부재 확정** (이론 예측)

## 7. 오늘 밟은 함정 (2026-08-05)

전부 **조용히 틀리는** 종류였다. 같은 실수를 되풀이하지 않게 적어둔다.

### ① 값을 바꾸는 탐색 루프는 끝나면 원복할 것

조향 한계를 찾는 `for V in 11400 11800 ...` 루프가 `steering_center_cdeg` 를 **11800 으로 남겨둔 채** 끝났다. 그 뒤 모든 주행이 **바퀴가 한쪽으로 꺾인 상태**에서 측정됐고, 네 개의 측정을 통째로 버렸다:

- 후진 60% → 10cm · 후진 100% → 25cm · 전진 43% 미동 · **"후진이 전진의 19%"**

그 위에 "후진이 구조적으로 약하다" 는 결론까지 쌓았다가 되돌렸다. **바퀴 위치가 아까와 다르다** 는 지적 하나로 잡혔다.

### ② 단계별로 재시작하면 변화가 안 보인다

브리지를 재시작할 때마다 워치독이 조향을 **중립으로 되돌린다**. 그래서 "중립 → 값 → 중립 → 값" 이 되어 단계 간 차이(400cdeg = 바퀴 2°)를 눈으로 못 본다. **브리지를 한 번만 띄우고 명령만 바꿔** 연속으로 훑을 것 — `scripts/steer_sweep.py` 가 그 용도다.

### ③ "멈췄다" 가 물리 한계가 아닐 수 있다

`atan` 때문에 명령이 커질수록 각도 증가폭이 줄고(2.1° → 1.2°/단계), 링키지 감속까지 겹치면 한 단계가 **바퀴 0.6°** 다. 자로도 0.2mm라 "멈춘 것" 으로 보인다. 실제로는 끝까지 따라오고 있었다.

가르는 법: **절대 위치를 직접 명령한다.** `angular_z = 0` 이면 브리지가 `steering_center_cdeg` 를 그대로 서보에 보내므로, 중립값을 바꿔 원하는 서보 위치로 보낼 수 있다(곡률 계산을 안 거친다).

### ④ `pkill -f <패턴>` 이 자기 셸을 죽인다

패턴이 자기 명령줄에도 매칭돼, 뒤에 붙은 명령이 **실행되기 전에** 끊긴다. 증상은 "값이 안 바뀌었다". 문자열을 쪼개 리터럴이 안 나타나게 한다: `pkill -f "uart_teleop""_bridge"`.

### ⑤ 브리지는 조용히 죽는다

ssh 세션이 정리될 때 딸려 죽는 일이 반복됐다. 죽으면 `/cmd_vel` 구독자가 0이 되고 **명령이 허공으로 가는데 로그는 정상으로 찍힌다.**

- 정렬 노드가 시작할 때 구독자를 3초 기다리고 없으면 **종료 코드 5** 로 끊는다
- 감시 스크립트(`/tmp/bridge_keepalive.sh`)를 띄워두면 죽어도 2초 뒤 되살아난다
- 생존 확인: `pgrep -cf "lib/forklift_teleop/uart_teleop""_bridge"` → **1**
