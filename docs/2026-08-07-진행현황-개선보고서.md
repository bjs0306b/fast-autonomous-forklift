## 5. 개선 방향 — 발견한 위험 7건

### 5.1 CRLF 때문에 리뷰가 불가능한 파일이 있다

`ai/src/control/fork_servo.py` 의 diff 는 **2574줄**이다. 그런데:

```bash
git diff --stat --ignore-all-space ai/src/control/fork_servo.py
#  1 file changed, 104 insertions(+), 8 deletions(-)
```

**실제 변경은 104줄인데 파일 전체가 재작성된 것처럼 보인다.** 줄바꿈이 CRLF 로
바뀐 탓이다. 이 상태로는 리뷰어가 실질 변경을 찾을 수 없고, 충돌이 나면 병합도
어렵다.

추적 파일 중 CRLF 는 4개다.

```
ai/scripts/onboard_fork_align_node.py
ai/src/control/fork_servo.py
ros2_ws/README.md
ros2_ws/src/forklift_teleop/behavior_trees/navigate_to_pose_no_spin.xml
```

**권장**: 저장소 루트에 `.gitattributes` 를 두어 고정한다.

```
* text=auto eol=lf
```

그 뒤 위 4개 파일을 LF 로 정규화해 **줄바꿈만 담은 커밋 하나**로 분리한다.
기능 변경과 섞으면 같은 문제가 반복된다.

### 5.2 안전 파라미터가 규격 문서와 갈라졌다 — 가장 중요

| 출처 | 정지거리 |
|---|---|
| `docs/ros2/obstacle-avoidance-validation.md:23,32` | **0.45 m** (두 곳에 명시) |
| `config/obstacle_avoidance.yaml` (현재) | **0.25 m** |

설정 주석에 "사용자 현장 충돌 방지 조치와 명시적 승인 하에" 라고 근거가 남아
있는 것은 좋다. 문제는 **검증 문서가 따라오지 않았다**는 점이다.

지금 상태로 4개 시나리오를 돌리면 합격 기준이 없다. 0.45 m 로 판정하면 전부
불합격이고, 0.25 m 로 판정하면 근거 문서가 없다.

**권장**: 검증 문서의 0.45 를 0.25 로 고치고, **왜 줄였는지와 남은 여유
(footprint 전면 0.190 m 대비 0.06 m)** 를 함께 적는다. 데모 전에 회피 시나리오를
다시 돌릴 계획이라면 이게 선행 조건이다.

### 5.3 벤더 패키지 2개가 버전 관리 밖에 있다

```
ros2_ws/src/rf2o_laser_odometry/     미추적
ros2_ws/src/ydlidar_ros2_driver/     미추적
```

`.gitignore` 에도 없다. **새로 클론하면 빌드가 안 된다.** 둘 다 주행에 필수인데
"어디서 받아서 어떻게 넣는지"가 어디에도 없다.

**권장**: 둘 중 하나를 고른다.

- 그대로 커밋한다 (재현성 확보, 저장소가 커짐)
- `.gitignore` 에 넣고 **설치 절차를 `ros2_ws/README.md` 에 적는다** (출처 URL·커밋 해시 포함)

어느 쪽이든 지금처럼 방치하는 것보다 낫다.

### 5.4 실행 절차가 지목하는 스크립트가 미추적이다

`ros2_ws/FIELD_SLAM_MQTT.md` 는 `tools/field_lap_session.sh` 를 실행 절차로
지목하는데, `ros2_ws/tools/` 전체가 미추적이다.

같은 디렉터리의 `left_recovery.py` · `rear_recovery.py` 는 문서가
**"임시 복구 스크립트부터 실행하지 말라"**고 경고하는 대상으로 보인다. 그렇다면
더더욱 버전 관리에 들어가서 무엇이 임시인지 표시돼야 한다.

### 5.5 정체불명 0바이트 파일 2개

```
./4?@W@8                                    0 bytes, Aug 5 12:57
./firmware/esp32/motor_controller/4?@W@8    0 bytes, Aug 5 12:57
```

잘못 입력된 명령의 부산물이다. 삭제한다.

### 5.6 커밋되지 않은 변경이 너무 크다

데모 3일 전에 **수정 18개 + 미추적 19개**, 커밋 0개. 되돌릴 지점이 없고 유실
위험이 크다. 지금 디스크가 날아가면 현장 튜닝 결과가 통째로 사라진다.

**권장**: 갈래별로 나눠 커밋한다. 뒤섞어 한 번에 커밋하면 문제가 생겼을 때 어느
변경이 원인인지 못 가린다.

1. 줄바꿈 정규화 (`.gitattributes` + 4개 파일)
2. 펌웨어 ToF INT 복구
3. 회피·구동 파라미터 현장 튜닝 (+ 검증 문서 갱신)
4. Nav2 운동 모델 (DUBIN·후진 금지)
5. 현장 SLAM 자동 한 바퀴 (신규 기능)
6. 트윈 텔레메트리 배선

### 5.7 텔레메트리가 조용히 꺼져 있다

`orin_telemetry.yaml` 의 `mqtt_enabled: false`, `origin_configured: false`.
노드는 정상 기동하고 로그도 정상으로 보이는데 **밖으로 아무것도 안 나간다.**

이 프로젝트는 같은 함정을 이미 겪었다 — MOVE 명령이 전부 거절되는데 그 사실이
아무 데도 안 찍혀 엉뚱한 곳을 팠다(S15P11A304-192). 그 교훈으로
`mqtt_bridge_node._build_command_adapter()` 는 **어느 쪽으로 떨어졌는지 반드시
로그에 남긴다.**

**권장**: 같은 패턴을 텔레메트리에도 적용한다. `mqtt_enabled: false` 이거나
`origin_configured: false` 면 기동 시 경고를 남긴다. "조용히 무력한 상태로 도는
일은 없어야 한다"는 원칙이 이미 코드에 있으니 그것을 따르면 된다.

## 6. 권장 순서 — 3일 기준

**유실·안전 위험이 먼저다. 기능 추가는 그 다음이다.**

| 순위 | 항목 | 근거 | 소요 |
|---|---|---|---|
| 1 | 갈래별 커밋 (§5.6) | 유실 위험. 지금 날아가면 복구 불가 | 30분 |
| 2 | 검증 문서 정지거리 정정 (§5.2) | 안전 기준이 없는 상태 | 15분 |
| 3 | `.gitattributes` + 줄바꿈 정규화 (§5.1) | 리뷰·병합 불가 해소 | 15분 |
| 4 | 벤더 패키지 처리 (§5.3) | 재현성 | 30분 |
| 5 | 현장 SLAM 한 바퀴 실주행 | 신규 1057줄이 미검증 | 반나절 |
| 6 | 구동 모터 EMI (I단계 잔여) | 주행 중 센서 신뢰성 | 10분 |
| 7 | 텔레메트리 발행 켜기 + 경고 추가 (§5.7, §4-2) | 트윈 연동 선행 조건 | 1시간 |
| 8 | 시뮬 규격 3건 합의 (§4-1,3,4) | 합의라 시간 예측 불가 — **오늘 착수** | — |

**8번을 오늘 시작할 것을 권한다.** 코드가 아니라 사람 사이의 합의라 리드타임이
길고, 정해지지 않으면 연동 코드를 써도 버려야 한다.

**5·6번은 데모 시연 내용에 직결된다.** 자동 한 바퀴를 시연할 계획이면 5번이
필수이고, 그 주행 중 센서가 흔들리면 6번이 원인일 수 있다.
