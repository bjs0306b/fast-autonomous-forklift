## 팀원별 Keep / Problem / Try

### 이준서 (팀장)

- **Keep**
  - Jira 작성이 아주 잘 이루어짐
  - 팀원들의 프로젝트에 대한 고민 및 책임감이 크다 느낌
- **Problem**
  - 아직은 크게 없다 느끼지만, Git 및 Jira — 기술 개발이 완료되면 바로바로 Merge Request 또는 스토리 및 에픽에 반영하기
- **Try**
  - Jira에 작성된 스토리 및 에픽이 끝나면 바로바로 반영하기
  - Git 기능 개발이 끝나면 바로바로 Merge Request 하기

### 김재원

- **Keep**
  - 프로젝트 요구사항과 역할을 초기에 구체적으로 정리하여 팀원별 담당 범위를 명확히 한 점
  - AI, 임베디드, 자율주행, 백엔드, 디지털 트윈 등 각 파트가 병렬로 준비할 수 있도록 업무를 분배한 점
  - Jira를 활용해 요구사항과 해야 할 일을 기록하고 프로젝트 진행 상황을 공유한 점
  - 실물 지게차와 시뮬레이션을 함께 활용하는 방향으로 3주 내 구현 가능한 범위를 조정한 점
- **Problem**
  - AI, ROS2, 백엔드, 디지털 트윈 간 통신 규격과 데이터 형식이 구체적으로 합의되지 않은 점
  - 개발 기간이 3주로 짧아 자율주행, 충돌 방지, 실시간 동기화까지 모두 안정적으로 구현하기에는 일정이 촉박한 점
- **Try**
  - Sprint 초반에 AI, ROS2, 백엔드, 디지털 트윈 간 MQTT Topic과 데이터 형식을 먼저 합의한다
  - 각 파트가 Mock 데이터를 활용해 실제 장비 연동 전에도 기능을 독립적으로 테스트한다
  - 핵심 시연 기능을 우선 구현하고, 충돌 예측이나 고급 통계 등 선택 기능은 후순위로 조정한다
  - 마지막 주에 통합을 시작하지 않고 Sprint 1부터 부분 연동 테스트를 진행한다

### 방지섭

- **Keep**
  - Sprint 0 목표였던 기획·설계를 8개 이슈 전부 완료로 마감했고, 요구사항 분석·개발환경·조사 항목이 팀원별로 고르게 분배돼 병목 없이 굴러갔다
- **Problem**
  - 작업 중에 이슈 상태를 옮기지 않고 막판에 몰아서 완료 처리해서 번다운이 우하향이 아니라 절벽으로 나왔고, 스토리 단위도 굵어서 중간 진척이 아예 보이지 않았다
- **Try**
  - 이슈를 착수하는 순간 바로 '진행 중'으로, 끝나는 즉시 '완료'로 옮긴다. 몰아서 처리하지 않는다

### 전지웅

- **Keep**
  - 임베디드 쪽 지식이 부족해 계획을 세우기 막막했던 부분이 있는데, 이번 주에 이 부분에 집중해 공부를 해 나가니 계획이 눈에 들어오기 시작해 좋았다
- **Problem**
  - 스프린트가 짧아 업무가 밀리지 않게 주의해야 하겠다는 생각이 들었다
- **Try**
