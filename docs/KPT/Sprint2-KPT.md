## 팀원별 Keep / Problem / Try

> K·P·T는 **각각 한 줄**로 적는다 ([KPT-가이드.md](KPT-가이드.md) §5).

### 이준서 (팀장)

- **Keep**
  - 팀원 모두가 적극적인 자세로 프로젝트에 참여하고 있음
- **Problem**
  - 구현 완료 후 Jira 상태를 즉시 반영하지 못하는 경우가 있음
- **Try**
  - 다음 주는 주요 부품이 모두 도착하는 실질적인 개발 주간인 만큼 각자의 진행 상황과 문제를 짧은 주기로 공유하기

### 김재원

- **Keep**
  - 팀원들이 각자의 역할에 책임감을 가지고 의견을 적극적으로 제시하며 프로젝트에 참여함
- **Problem**
  - 구현한 기능과 변경 사항이 Jira에 즉시 반영되지 않아 실제 진행 상황과 이슈 상태가 달라지는 경우가 있음
- **Try**
  - 본격적인 구현 및 통합에 맞춰 각자의 진행 상황과 발생한 문제를 짧은 주기로 공유하고 Jira 상태도 함께 갱신하기

### 방지섭

- **Keep**
  - 작업 착수 및 완료 시 Jira 상태를 바로 변경해 보드에서 진척 상황을 파악할 수 있도록 했고, Jira 관리자로서 스프린트 운영 규칙을 유지함
- **Problem**
  - 스테이션 및 AI 작업을 혼자 진행하면서 협업 접점이 부족했고, 진행 상황과 블로킹 요소를 스크럼에서 충분히 공유하지 못해 팀의 문제 인지가 늦어짐
- **Try**
  - 장기 작업을 서브 스토리로 분할하여 라벨링 및 데이터 수집을 팀원과 분담하고, 매일 스크럼에서 진행 상황과 블로킹 요소를 공유하며 Jira 운영 규칙을 재점검하기

### 안제원

- **Keep**
  - ROS 설정 및 SLAM 구동에 성공함
- **Problem**
  - VL53L8CX 센서 2개가 손상됨
- **Try**
  - 포크리프트 구동 및 ToF 센서 구현 진행

### 전지웅

- **Keep**
  - 각자 맡은 부분이 끝나면 유기적으로 서로 도우려는 팀워크가 좋았음
- **Problem**
  - 일부 인원에게 태스크가 몰리지 않도록 더 적극적으로 업무 분담에 참여할 필요가 있음
- **Try**
  - Jira 이슈를 더 세분화하여 현재 어떤 업무를 수행하고 있는지 구체적으로 공유하기

### 전희창

- **Keep**
  - 주어진 기능 구현에 그치지 않고 ESP32-S3, FreeRTOS, I2C, ROS2 텔레옵까지 연결되는 전체 구조를 구상하며 아이디어를 구체화함
- **Problem**
  - Motor Driver HAT의 5V 전원 누락처럼 하드웨어 사양과 배선을 충분히 확인하지 않아 디버깅에 시간이 소요됨
- **Try**
  - UART·ROS2 연동, 안전 정지, 명령 구조 등 주어진 업무 외 추가 기능까지 먼저 설계하고 직접 구현을 시도하기
