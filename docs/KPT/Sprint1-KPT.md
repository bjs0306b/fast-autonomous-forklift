### 김재원

- **Keep**
  - 기존 코드를 먼저 분석하고 부족한 부분만 보완했다. MQTT 수신, DB 저장, WebSocket 전송을 분리했고, current/history를 같은 트랜잭션으로 처리했다. QoS 1, retained false, 예외 격리, 문서화와 테스트도 잘 유지했다.
- **Problem**
  - ROS2 실제 차량 제어, ROS2 Bridge 실연결, 프론트 STOMP 구독, Broker 재연결, EC2 보안 설정은 아직 미검증 또는 미구현이다. 상태 이력 조회 API도 페이지네이션과 기간 조회가 부족하다.
- **Try**
  - ROS2 명령 인터페이스를 확정하고 실제 차량 제어 어댑터를 구현한다. ROS2·임베디드·프론트와 함께 상태 수신부터 명령 결과 회신까지 End-to-End 테스트를 진행한다. EC2 Broker 인증과 접근 제한, 재연결 검증, 상태 이력 API 보강도 진행한다.

### 방지섭

- **Keep**
  - 감지 도메인 갭을 데이터로 정면 돌파했다. 공개셋(LOCO+Cardboard)에 LSCD를 한 학습셋으로 섞은 단일 run으로 pallet 망각 없이(0.623→0.679) **실험5 mAP_50 0.753 달성**(목표 0.72 초과), 2단 순차 파인튜닝 폐기 판단이 실증으로 옳았다.
  - 스테이션 측정 서비스를 실물로 관통했다. BRIO+TF-Nova+ONNX로 박스 감지 score 0.66~0.86, 치수 실측 대조 오차 <0.6cm로 KPI(≤4mm 환산) 통과 — 코드뿐 아니라 실장비 E2E까지 확인.
  - Sprint 0 Try("착수 즉시 진행 중 / 끝나면 즉시 완료")를 지켜, 번다운이 단일 절벽에서 계단형으로 바뀌었다(중간 진척 가시화).
- **Problem**
  - 번다운 곡선이 스프린트 내내 가이드라인 위에 있었다. 7/21·7/22 두 차례 스토리를 도중 투입(스코프 유입)해 커밋을 고정하지 못했고, 7/24 오후 47→24로 막판 몰림이 재발했다.
  - 스테이션·AI 계열(69·32·156·148)을 혼자 다 쥐어 35 SP를 배정받았고, 32·69 MR이 156 리그 파인튜닝에 물리는 상호 블로킹으로 1인 병목이 됐다. 완료 17/35에 그쳐 진행 중이 대거 이월됐다.
  - 검은 플라스틱 파렛트 미검출을 스프린트 막판(7/24)에야 발견했다. 실물 파렛트 도착을 전제로 한 검증이 크리티컬 패스에 있어 편하중 E2E를 스프린트 안에 못 닫았다.
  - 편하중(FR-104)이 파렛트 감지에 의존하는데 모델이 검은 파렛트를 못 잡아 파렛트 중심을 눈대중 고정 ROI로 주입 → 파렛트 상대 판정이라는 핵심은 반쪽 검증에 그쳤다.
- **Try**
  - 스프린트 시작 시 커밋 스코프를 고정하고, 도중 발견된 작업은 원칙적으로 다음 스프린트 백로그로 보낸다(불가피한 유입만 예외 처리·기록).
  - 스테이션·AI 장기작업은 착수 시점에 서브 스토리로 쪼개고 데이터 라벨링·보강 등 병렬화 가능한 조각은 팀원에게 넘겨, 1인 배정 SP를 20 이하로 관리한다.
  - 하드웨어(실물 파렛트·리그) 의존 검증은 "물건 도착 = 즉시 착수" 대신 도착 전 폴백(고정 ROI 정밀 캘리)을 먼저 준비해 크리티컬 패스에서 뺀다.
  - 도메인 갭 리스크는 스프린트 초반에 실물 1컷 스모크 테스트로 조기 확인해, 미검출 발견이 막판으로 밀리지 않게 한다.
